    New Components¶

    spyre-device-plugin-init¶

    A new standalone init-container component that performs hardware topology discovery (topo.json) before the device plugin starts. Runtime interaction with physical hardware is handled by an on-demand sidecar image (spyre-runtime-ctk) that is now decoupled from the main binary, keeping the init container lean and avoiding a permanent runtime process on the node.

    • Configure via spec.devicePlugin.initContainer in SpyreClusterPolicy.
    • When running against physical devices, the runtime image must be supplied via spec.devicePlugin.initContainer.runtime. Without it, physical device discovery and topology generation will be skipped or incomplete.
    • See Device Plugin Guide for configuration details.

    spyre-metrics-exporter¶

    The metrics exporter is promoted from an internal helper to a first-class open-source component.

    Key architectural change: the embedded Prometheus scrape program (promclient.py) has been replaced by spyre-metrics-api, a purpose-built metrics API library. Hardware-level PF metric parsing now relies on spyre-runtime-ctk, which is injected as an on-demand runtime sidecar — the same decoupled pattern used by spyre-device-plugin-init.

    • When reading PF card metrics from physical hardware, the runtime image must be supplied via spec.metricsExporter.runtime.
    • See Metrics Exporter Guide for configuration details.

    New Features¶

    VF (Virtual Function) Device Support in DRA Driver¶

    The DRA driver (dra-driver-spyre) now discovers and manages Virtual Function (VF) devices in addition to Physical Functions (PF). New DeviceClass objects and updated MachineConfig manifests are provided to support VF workloads in a DRA-managed cluster.

    See DRA Driver Guide for prerequisites and configuration.

    Reporter Framework in spyre-health-checker¶

    A new extensible reporter framework has been introduced in spyre-health-checker. Two reporters ship in v1.4.0:

    Reporter Description
    lspci (default) Existing PCI device liveness check.
    RASWatcher Detects failed-pod logs and surfaces RAS events.
    CardmgmtReporter Connects to the card management service via the new secured UNIX-socket gRPC endpoint, enabling direct interaction with the card management service and correct pci_address labeling in exported metrics.

    Configure which reporters are active via spec.healthChecker.enabledReporters (see API Changes below).

    Card Management — gRPC Service Endpoint¶

    spyre-card-management now exposes a gRPC service endpoint that wraps the existing pyrpc interface. The service is accessible via a secured UNIX domain socket and is used by CardmgmtReporter in spyre-health-checker. The socket is managed by the new spec.cardManagement.healthApi sidecar (see API Changes below).

    Prometheus Scraping for spyre-health-checker¶

    spyre-health-checker now exposes a dedicated /metrics endpoint on port 8081 and the operator deploys the supporting Kubernetes resources automatically alongside the DaemonSet:

    Resource Name Description
    Service spyre-health-checker ClusterIP service targeting port 8081 on all health-checker pods.
    ServiceMonitor spyre-health-checker Prometheus Operator ServiceMonitor that scrapes the service every 30s.

    No additional configuration is required — both resources are created whenever spec.healthChecker is enabled.

    New OpenShift Dashboard Row — "Spyre Device State"¶

    The OpenShift dashboard (deployed as a ConfigMap in the openshift-config-managed namespace) gains a new "Spyre Device State" row driven by the spyre_device_state metric emitted by spyre-health-checker.

    The row contains two panels side by side:

    Panel Type Query Description
    Device State Count by Node / State / Type Table sum by (node, state, devicetype) (spyre_device_state{node=~"$node"}) Instant snapshot of device counts broken down by node, health state, and device type.
    Device State Distribution Stacked bar chart sum by (node, state, devicetype) (spyre_device_state{node=~"$node"}) Time-series view of device state changes over the selected time range.

    [!NOTE] The dashboard ConfigMap has been moved to the common/ state-init path and is now always deployed regardless of which optional components are enabled. Previously it was only deployed when the metrics exporter was present.

    API Changes¶

    New Fields¶

    spec.devicePlugin.initContainer.runtime (object, optional)¶

    Configures the runtime sidecar for the device-plugin init container. Accepts a full DeploymentConfig block (repository, image, version, args, env, resources, nodeSelector, etc.).

    spec:
  devicePlugin:
    initContainer:
      repository: "quay.io/ibm-aiu"
      image: "spyre-device-plugin-init"
      version: "1.4.0"
      executePolicy: IfNotPresent
      runtime:
        repository: "quay.io/ibm-aiu"
        image: "spyre-runtime-ctk"
        version: "v1.3.0"

    spec.metricsExporter.runtime (object, optional)¶

    Configures the runtime sidecar for the metrics exporter, providing spyre-runtime-ctk with the monitor library needed for reading PF metric files. Accepts a full DeploymentConfig block.

    spec:
  metricsExporter:
    runtime:
      repository: "quay.io/ibm-aiu"
      image: "spyre-runtime-ctk"
      version: "v1.3.0"

    spec.cardManagement.healthApi (object, optional)¶

    New sidecar for the card management DaemonSet that exposes the gRPC health-check API via a UNIX domain socket.

    Sub-field Type Default Description
    enabled bool false Deploy the sidecar.
    (other) DeploymentConfig — image, args, env, resources, etc. 
    spec:
  cardManagement:
    healthApi:
      enabled: true
      repository: "quay.io/ibm-aiu"
      image: "spyre-cardmgmt-health-api"
      version: "1.4.0"

    spec.healthChecker.enabledReporters (string, optional)¶

    Comma-separated list of reporters to activate in spyre-health-checker.

    Value Description
    lspci,cardmgmt Default — both reporters active.
    lspci Disable the cardmgmt reporter (e.g., when card management is not deployed). 
    spec:
  healthChecker:
    enabledReporters: "lspci"

    Default Value Changes ⚠️ Breaking¶

    The following field defaults have been cleared in v1.4.0. Existing SpyreClusterPolicy resources that relied on the implicit defaults will need explicit values set after upgrading.

    Field v1.3.0 default v1.4.0 default
    spec.cardManagement.pfRunnerImage docker.io/spyre-operator/spyredriver-image:latest ""
    spec.cardManagement.vfRunnerImage docker.io/spyre-operator/spyredriver-image:latest ""
    spec.metricsExporter.metricsPath /data ""

    [!IMPORTANT] If your existing SpyreClusterPolicy does not specify cardManagement.pfRunnerImage, cardManagement.vfRunnerImage, or metricsExporter.metricsPath explicitly, you must add them before upgrading to v1.4.0, or the card management and metrics exporter components will fail to start.

    Security Fixes¶

    Area Detail
    Webhook validation bypass A functional security bug that allowed crafted pod specs to bypass admission validation has been fixed in spyre-webhook-validator.
    CVE fix CVE PVR0822046 patched in spyre-webhook-validator.
    mTLS enforcement Mutual TLS is now enforced on the health-check gRPC stream in spyre-health-checker.
    TLS verification TLS certificate verification is now enforced in spyre-device-plugin.

    CI / Engineering Changes¶

    Area Detail
    End-to-end tests CRC (CodeReady Containers) e2e test suite enabled in CI pipeline.
    Go version Upgraded from Go 1.25.9 to Go 1.26.7 across all components.

    Migration Guide¶

    See Default Value Changes above for the fields that must be set explicitly before upgrading existing SpyreClusterPolicy resources to v1.4.0.
